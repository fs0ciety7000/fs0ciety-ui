# fs0ciety — Roadmap + M1 `@fs0lab/tokens` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@fs0lab/tokens` 0.1.0: the W3C DTCG source of truth for fs0ciety, built to CSS variables (3 themes), a typed JS/TS module, a Tailwind v4 theme and Figma-importable JSON, with WCAG contrast checked in CI.

**Architecture:** DTCG JSON files under `packages/tokens/tokens/` (primitives, then one semantic file per theme). A Style Dictionary 5 build script (`scripts/build.mjs`, plain ESM so it runs on Node 22 without a TS loader) resolves aliases and writes `dist/css/tokens.css`, `dist/tailwind.css`, `dist/figma/*.json` and `src/generated/tokens.ts`. `src/generated/` is gitignored, and `tsdown` bundles `src/index.ts` into `dist/index.mjs`. Every later package reads tokens only through `--fs-*` CSS variables or this module.

**Tech Stack:** pnpm 11, Turborepo, TypeScript 6, Style Dictionary 5.8, culori 4 (OKLCH conversion, ΔE), apca-w3 0.1.9 (informative APCA), Vitest, Biome.

**Spec:** `DESIGN.md` (the token values), `docs/brief.md` (scope), `CLAUDE.md` (conventions).

## Global Constraints

- Node `>=22`, pnpm 11, TypeScript `^6` (not 7: svelte-check and @astrojs/check do not support it), ESM only, `"type": "module"`.
- Every color source value is OKLCH. CSS output uses `oklch(L% C H)` or `oklch(L% C H / A)`. No hex fallback (Baseline 2024).
- Token values are copied verbatim from `DESIGN.md`. If a value seems wrong, stop and ask; never "fix" it silently.
- CSS custom properties are prefixed `--fs-`, primitives `--fs-color-<hue>-<step>`, semantic roles `--fs-<role>`.
- Theme switch: `data-fs-theme="schematic|night|light"`. With no attribute, schematic applies, or light under `prefers-color-scheme: light`.
- All CSS output is wrapped in `@layer fs.tokens`.
- Importing the JS module must not touch `window` or `document` (SSR-safe). `sideEffects: ["**/*.css"]`.
- Package license MIT. `publishConfig.provenance: true`.
- Biome formatting (tabs, double quotes). Commit messages follow Conventional Commits.

## Review Focus

1. **Broken alias**: a semantic token pointing at a missing primitive must fail the build with the token path in the message, never emit `undefined` or an empty variable. → Task 2.
2. **Nested themes**: `<div data-fs-theme="light">` inside a night page must get light values. Theme selectors must therefore match any element, not only `:root`. → Task 5.
3. **No attribute + light OS preference**: an unthemed `<html>` on a light-mode OS gets light values, but an explicit `data-fs-theme="schematic"` still wins. → Task 5.
4. **Alpha colors**: `backdrop` (72 % and 40 %) and the glow shadows must keep their alpha in the CSS, Tailwind and Figma outputs (`/ 0.72`), not drop to opaque. → Tasks 2, 5 and 6.
5. **SSR import**: `import { themes } from "@fs0lab/tokens"` in a plain Node process (no DOM) works, and `@fs0lab/tokens/css` resolves through the exports map from a consumer package. → Tasks 6 and 7.
